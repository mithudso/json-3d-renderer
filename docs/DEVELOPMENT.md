# Development

_Snapshot: 2026-06-20._

## Prerequisites

- A modern browser (WebGL support for the 3D view).
- Optional: Python 3 or Node.js, only to run a tiny static file server for local viewing.

There is **no build step, no `package.json`, and no test suite** checked into this repo
today. Do not document or assume one that doesn't exist (see
[known-issues.md](known-issues.md) for why the generators are absent).

## Viewing the demos locally

The demo pages load a rendering library by relative path, so serve the repo over HTTP rather
than opening `file://` URLs:

```sh
# from the repo root
python3 -m http.server 8000
#   → http://localhost:8000/examples/concept-tree-3d.html
#   → http://localhost:8000/examples/concept-tree.html
#   → http://localhost:8000/examples/skills-graph.html

# or, with Node installed:
npx --yes serve .
```

> ℹ️ The demo pages load their library from the repo root via a `../` relative path
> (`../concept-tree-3d.bundle.js` / `../d3.v7.min.js`), fixed 2026-06-20. Serve from the repo
> root (as above) so the `../` resolves. Because these are **generated** files, the same fix
> must also be made in the upstream generator or it will regress on regeneration — see
> [known-issues.md](known-issues.md).

## Verifying a page renders

1. Open the page through the local server.
2. Open the browser **console** — a blank canvas almost always means the library failed to
   load (the path issue above) or `DATA` failed to parse.
3. For the 3D page, you should see the control panel (search, **Radial / Tree / Free** layout
   buttons, domain chips) and a node count readout. Click a node to isolate its neighbors and
   open the details panel.

## Editing data or output

- The `.html`, `.md`, and `.mmd` files under `examples/` are **generated** (first line is a
  `GENERATED by scripts/…` banner). Hand-edits are lost on regeneration. To change them for
  real, change the upstream generator (not in this repo — see
  [known-issues.md](known-issues.md)) or open an issue to vendor the generators in.
- To experiment by hand on a one-off basis, edit the inlined `const DATA = {...}` literal
  directly in a page and reload. Note in any PR that the edit is non-durable.

## Validation

The only automated check is JSON validity, enforced in CI
(`.github/workflows/ci.yml`). To run the same check locally:

```sh
git ls-files '*.json' | while read -r f; do
  node -e "JSON.parse(require('fs').readFileSync('$f','utf8'))" && echo "ok: $f" || echo "BAD: $f"
done
```

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| Blank page / nothing renders | Library failed to load | Confirm you're serving from the repo root so `../<library>` resolves; check the console |
| `THREE is not defined` / `ForceGraph3D is not defined` in console | 3D bundle didn't load | Verify `../concept-tree-3d.bundle.js` exists relative to the page |
| 2D page empty | `d3.v7.min.js` didn't load | Verify `../d3.v7.min.js` exists relative to the page |
| Counts differ between pages/docs | By design — each artifact counts a different slice | See [known-issues.md](known-issues.md) |
